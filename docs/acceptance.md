# Приёмка перед 1.0

Состояние на 20.10.2026. Linux CI и ручная приёмка на Ravelin учитываются отдельно.

| Проверка | Подтверждение |
| --- | --- |
| Пассивные CLI/TUI, наблюдение v2, службы ICMP/WSS | Вывод пользователя с Ravelin |
| Клиенты VLESS и генерация подписок | Подтверждено пользователем |
| Приоритет primary 10 → 15 → 10 | Ravelin, v0.4.2; основной выход сохранён |
| Maintenance on/off резервного forpost1 | Ravelin; возврат Standby/Healthy |
| Stop резервного forpost1 | Ravelin, v0.6.0; AWG/транспорт inactive, marker сохранён |
| Откат неудачного Start | Ravelin, v0.6.0; Stopped/Down, marker и оба guard сохранены |
| ICMP Start с ручным серверным reset | Ravelin, v0.6.1; HTTPS 3/3, Maintenance, затем Standby/Healthy |
| Starting / Waiting for server | Новое отображение 0.6.2; приёмка на Ravelin предстоит |
| Stop/Start через TUI | Требует отдельного подтверждения владельцем |
| Stop/Start WSS | Linux-модель проверяет порядок/откат; на серверах не принято |
| Сохранение Stop после reboot | Условие systemd проверяется в CI; сервер не перезагружался для приёмки |
| Нагрузка текущей версии | Требует свежих измерений на Ravelin |
| iperf3 | Код доступен; подготовленного внутреннего сервера пока нет |

## Следующие шаги

1. Установить 0.6.2, проверить обычный статус и работу collector без сетевых изменений.
2. При ближайшем плановом тесте резервного forpost1 проверить TUI: m → Maintenance,
   x → Stop, s → Start с отдельной готовой консолью Forpost1. После `[WAIT]` вручную
   перезапустить только серверный udp2raw transport. Во второй консоли Ravelin
   `warden status --live` должен показать Starting / Waiting for server; после
   HTTPS 3/3 — Maintenance, после отдельного m/off — Standby/Healthy.
   Если восстановление прошло слишком быстро, фазу можно не успеть увидеть.
3. Отдельно согласовать тест WSS, предварительно убедившись, что другой текущий
   выход устойчиво Healthy. При одновременных сбоях ICMP рабочий WSS не останавливать.
4. Сохранение Stop после reboot проверить только в плановое окно владельца, с
   независимой консолью. Не перезагружать рабочий шлюз ради проверки интерфейса.
5. После обычной работы снять память/рестарты collector и проверить историю/трафик.
   Только затем решить, достаточно ли эксплуатационной приёмки для 1.0.

Начальная проверка нагрузки только читает состояние:

```bash
warden --version
warden doctor --json
systemctl show warden-collector.service \
  -p ActiveState -p SubState -p NRestarts -p MemoryCurrent -p MemoryPeak -p MemoryMax
```

1.0 не объявляется автоматически по успешному CI. Исследование ICMP reconnect без
ручного серверного reset — отдельная работа с транспортом; оно не входит в 0.6.2.
