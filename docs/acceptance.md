## Дальнейшая эксплуатация и границы приёмки

1. 0.6.5 установлена; основные CLI/TUI-сценарии, Hysteria2 и обратный WSS приняты.
   Подготовка стабильного выпуска не требует специальной перезагрузки шлюза.
2. Цикл forpost1 через TUI принят: повторять его после каждого обновления не нужно.
   Нынешний Forpost1 использует Hysteria2; перезапуск старого серверного ICMP к нему
   не относится. Ручной server reset остаётся сценарием только оставшихся ICMP-каналов.
   Отображение кратких переходных фаз отдельно не подтверждено скриншотом/выводом.
3. Цикл обратного WSS Forpost3 принят. Повторные остановки ради приёмки не нужны.
   При одновременных сбоях других выходов рабочий WSS не останавливать.
4. Проверка Stop после reboot исключена по решению владельца. Не планировать её
   автоматически и не описывать результат как подтверждённый на сервере.
5. Память/рестарты collector и история/трафик остаются предметом обычного наблюдения;
   опубликованные замеры не доказывают отсутствие роста памяти при любой нагрузке.

Начальная проверка нагрузки только читает состояние:

```bash
warden --version
warden doctor --json
systemctl show warden-collector.service \
  -p ActiveState -p SubState -p NRestarts -p MemoryCurrent -p MemoryPeak -p MemoryMax
```

1.0 не объявляется автоматически по успешному CI. Исследование ICMP reconnect без
ручного серверного reset — отдельная работа с транспортом; оно не входит в 0.6.4.
