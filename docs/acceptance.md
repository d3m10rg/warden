## Следующие шаги

1. Установить 0.6.4 с поддержкой Hysteria2 и зависимости обратного WSS.
   Проверить версию, обычный статус и работу collector без сетевых изменений.
2. Цикл forpost1 через TUI принят: повторять его после каждого обновления не нужно.
   Нынешний Forpost1 использует Hysteria2; перезапуск старого серверного ICMP к нему
   не относится. Ручной server reset остаётся сценарием только оставшихся ICMP-каналов.
   Отображение кратких переходных фаз отдельно не подтверждено скриншотом/выводом.
3. Продолжить поэтапный тест обратного WSS Forpost3 после установки 0.6.4,
   предварительно убедившись, что другой текущий
   выход устойчиво Healthy. При одновременных сбоях ICMP рабочий WSS не останавливать.
4. Сохранение Stop после reboot проверить только в плановое окно владельца, с
   независимой консолью. Не перезагружать рабочий шлюз ради проверки интерфейса.
5. После обычной работы снять память/рестарты collector и проверить историю/трафик.
   Только затем решить, достаточно ли эксплуатационной приёмки для 1.0.

Начальная проверка нагрузки только читает состояние:

```bash
warden --version
warden doctor --json
systemctl show warden-collector.service \
  -p ActiveState -p SubState -p NRestarts -p MemoryCurrent -p MemoryPeak -p MemoryMax
```

1.0 не объявляется автоматически по успешному CI. Исследование ICMP reconnect без
ручного серверного reset — отдельная работа с транспортом; оно не входит в 0.6.4.
